ตัวนับ ACK ช่วงแรกก่อนรีบูต Node มีประวัติที่ส่งไม่สำเร็จอยู่ ไม่ใช้ยอดรวมชุดนั้นอ้าง packet delivery rate ใหม่; ช่วง 114/114–125/125 เป็นเพียงช่วงสั้นที่สังเกต ไม่ใช่ผลทดสอบระยะยาว

## ผลทดสอบรอบ 2–3 (18 พ.ย. 2026 ~03:09–04:03)

### Gateway รับค่าจริง (local test channel 1)
- อัปโหลด Gateway (COM7, CH343 SER=5A4F014304) สำเร็จ 72 s; บูตขึ้น `local test, channel 1, cloud disabled`
- Gateway log: `new node 1`, `Sensor node 1 back: closed loop resumed`, `node 1 seq=2..51 lux=37.50` — ค่าใกล้กับที่ Node อ่าน (≈33–37 lx) แต่ยังไม่ได้เทียบ seq ต่อ seq พร้อมกันสองฝั่ง
- heartbeat ช่วงนั้นรายงาน `reset=9` (ESP_RST_BROWNOUT) ขณะ Node ใช้หัวชาร์จ/สาย USB-A→C; ภายหลังเห็น `E BOD: Brownout detector was triggered` อีกครั้งระหว่างแก้สายตอนบอร์ดมีไฟ
- สาย USB-A→C เส้นนั้นไม่ขึ้นพอร์ตข้อมูลบนคอม และตอน Gateway ใช้สายเส้นนั้น ACK ของ Node ตกเหลือราว 33/87 ในช่วง 30 s; หลังเปลี่ยนแหล่งไฟ Gateway ได้ tx=411/411 ต่อเนื่อง (~5 นาที) — สอดคล้องกับสมมติฐานไฟเลี้ยงไม่พอ แต่ยังไม่ได้ดู log Gateway ระหว่างช่วงที่หลุด
- ระหว่างนั้นพบ `BH1750 missing (0x23)` จากสายหลวม; แก้สายแล้วกลับมา found

### TCS34725
- ต่อแยกบัส: SDA=GPIO10, SCL=GPIO11 (Wire1), VIN→3V3, GND, LED→GND, INT/3V3 ไม่ต่อ
- ตรวจพบ `TCS34725 found (0x29, SDA=10 SCL=11)`, tcs_ok=1
- gain 1x ให้ค่าดิบต่ำมากในห้อง ~36 lx (c≈6, cct กระโดด 2661↔3296) จึงเปลี่ยนเป็น 16x

| สภาพ (gain 16x) | r / g / b / c | cct |
|---|---|---|
| ไฟห้อง (ไฟโทนวอร์ม) | 67 / 41 / 26 / 141 | 2870 K นิ่ง |
| ไฟฉายมือถือ | ≈1,850 / 1,470 / 1,210 / 4,700 (ใกล้กว่า: 7,708 / 6,000 / 5,051 / 19,398) | ≈3,850–3,890 K |
| วัตถุสีแดง | ≈117–136 / 37–46 / 27–32 / 183–218 | ≈2,250–2,330 K |
| วัตถุสีน้ำเงิน/เขียว | ไม่ได้ทดสอบแยก — ผู้ทดสอบถือว่าผลไฟห้อง/ไฟฉาย/สีแดงเพียงพอสำหรับยืนยันการทำงาน | — |

ทิศทางค่าเป็นไปตามคาด (แดงทำให้ r เด่นและ cct ต่ำลง; ไฟฉายสว่างและ cct สูงขึ้น) แต่ cct ของไฟฉาย (~3,900 K) ต่ำกว่าที่มักพบในไฟฉายมือถือ จึงยังไม่ใช้เป็นค่าความแม่นยำ ต้องเทียบกับแหล่งแสงที่รู้ค่า/เครื่องวัดก่อน
